## 1. 문제 인식과 결론

**초기 4주 풀 플랫폼 계획**은 솔로·병행 일정 기준으로 과도했다.

**결론:** MVP로 슬라이스하고, 검색·리뷰·풀 관리자 UI 등은 **Phase 2(취업 후·여유 시)** 로 연기한다. 완벽한 UI보다 **작동·검증 가능한 스토리**를 우선한다.

## 2. MVP에서 증명할 것 / 하지 않을 것

### 증명 (4주 안)

- UGC **동작** (비주얼 에디터 수준 아님)
- 멀티 유저·세션 **격리**
- **BYOK** + 무료 티어 **쿼터**
- **Feature Flags**로 비용·가입 제어
- **실제 배포**(AWS 등)와 HTTPS
- 확장 시 **무엇을 키워야 하는지**(설정 + 인프라) 설명 가능

### 하지 않음 (MVP)

- SNS급 UI/UX
- 공개 탐색·검색·리뷰 시스템
- “코드 변경 없이 무한 확장” 같은 **과장** (아래 면접 스크립트 참고)

## 4. 정책 숫자 통일 (문서·README 공통)

혼동을 없애기 위해 **역할을 분리**한다.

| 개념 | 값 | 설명 |
|------|-----|------|
| **정책 상한** `MAX_TOTAL_USERS` | 100 (예시) | 가입 가능한 계정 수 **상한**. Feature Flag·DB로 제어 |
| **1차 베타 코호트** | ~10명 | 실제 초대할 사람 수. 모니터링·피드백용 |
| 무료 티어 일일 턴 | 20 | 플랫폼 키 사용 시 |
| 월드/인 (MVP) | 3 | Feature Flag와 일치 |
| 플랫폼 월 비용 **목표 상한** | ~$700 | 아래 비용 절 참고 |

README·발표 자료에는 **“비공개 베타, 초대 필요, 정책상 한도 N명”**처럼 쓰고, **실제 초대는 10명 근처**라고 구분해 적는 것을 권장한다.

---

## 5. 비용 (예산 vs 실측)

- **예산(보수적 가정):** 예) `$0.011/턴` × (100명 × 20턴 × 30일) ≈ **$660/월** — 플랫폼 키(무료 티어만) 기준 상한 추정.
- **실측:** 기존 엔진의 **`UsageTracker`** 및 Anthropic `usage`(input/output/cache)로 턴마다 합산. 캐시·2-pass·출력 길이에 따라 변동.
- **BYOK:** 해당 턴 비용은 **사용자 계정**에 청구. 플랫폼 비용 집계에서 **제외**.
- **알림:** 일일 플랫폼 비용 임계(예: $50) 초과 시 알림 + `EMERGENCY_SHUTDOWN` 등 문서화된 경로.

인프라(RDS·EC2)는 **별도**로 잡는다(베타 월 수십 달러 전후 가정 등).

---

## 6. 보안·개인정보 (MVP)

- 사용자 API 키: **암호화 저장(Fernet 등)**, 마스터 키는 시크릿 스토어. **운영자는 기술적으로 복호화 가능**함을 처리방침에 명시.
- 베타: 신뢰 가능한 소수만 초대해도, **최소한의 개인정보·키 취급 문구**는 두는 것을 권장.
- `.env`를 EC2에 `echo`로만 두지 말고 **SSM Parameter Store / Secrets Manager** 등을 목표로 명시.

---

## 7. 배포·Docker 원칙 (요약)

- **의존성:** 저장소는 **Poetry** 기준 — 이미지 빌드 시 `poetry install` 패턴.
- **마이그레이션:** 앱 워커 기동과 분리(전용 one-shot job / init 컨테이너). 여러 worker가 동시에 `alembic upgrade` 하지 않도록.
- **uvicorn workers:** 베타는 **2**부터(메모리). t3.small 등에서 4 worker는 과할 수 있음.
- **Feature Flags:** 멀티 워커면 클래스 변수만으로는 불일치 가능 — **DB(또는 Redis) 읽기** + 필요 시 짧은 TTL 캐시.

---

## 8. 타임존

- DB: **UTC (`TIMESTAMPTZ`)**, 일일 쿼터 리셋 기준은 **문서에 한 가지로 고정**(예: UTC 자정).
- UI: 사용자 로컬 표시만 달리 할 수 있음.

---

## 9. 데이터·스키마 주의 (MVP)

- `users.created_worlds`에 **CHECK로 3 고정**하지 말고, **`worlds` COUNT** 또는 트리거로 정책 일치.
- `invite_codes.created_by`: 관리자 삭제 시 초대 행이 사라지지 않게 **`ON DELETE SET NULL`** 등 검토.
- **단일 진실의 원천:** 플레이 상태·장기 기억을 DB에 둘 때, 파일 `memories.json`과 **이중 갱신**되지 않게 경계를 한 번에 정한다.

## 11. 병행 개발 전략 (프론트 동시)

API만 주 단위로 쌓았다가 나중에 UI를 붙이면 **응답 스키마·에러 형식**을 다시 깨기 쉽다. MVP는 **수직 슬라이스(Vertical Slice)** 로 간다: **작은 API → 같은 날/다음 날 UI → 연동 확인**.

### 11.1 핵심 원칙

| 원칙 | 설명 |
|------|------|
| **수직 슬라이스** | API 조금 → UI 바로 → 연동 테스트. 주 단위로 “보이는” 완성품을 만든다. |
| **필수/선택 분리** | 각 Week 말에는 **필수**만 달성. 선택은 **다음 Week 초**로 이월 가능. |
| **주말 버퍼** | 토·일: 버그픽스, 밀린 작업, 스타일 보완, **다음 주 준비**. |

### 11.2 Day 0 체크리스트 (연동 전에 끝낼 것)

- [ ] FastAPI **CORS** (`CORSMiddleware`, 허용 오리진)
- [ ] 프론트 **`VITE_API_URL`** (또는 Vite proxy) 확정
- [ ] 로컬 포트 통일 예: API `http://localhost:8000`, Vite `http://localhost:5173`
- [ ] **`.gitignore`**: `.env`, 키·시크릿·`node_modules`·빌드 산출물 미커밋 확인

### 11.3 주차별 “끝에 보이는 것”

| 주차 | 백엔드(요약) | 프론트(요약) | 주말 끝 상태 |
|------|--------------|--------------|--------------|
| **Week 1** | DB, signup/login, JWT, `invite_code` **필드** | Vite·Router, 로그인/가입(초대 입력란) | **로그인·가입·JWT 보호 페이지** (스크린샷 가능) |
| **Week 2** | 초대 검증·BYOK(이월분), 월드 CRUD | 목록·생성 폼·설정(키) | **월드 CRUD + 이월된 인증 보강** |
| **Week 3** | GameEngine·세션·공유 (초반 집중) | 채팅·게이지 (후반 집중) | **플레이 한 사이클** |

## 12. MVP 성공 기준 (완화된 베타)

**기술**

- Week 1~2에 걸쳐 초대 검증·BYOK를 포함해 **로그인~월드**가 동작하고, 이후 공유·플레이·세션 격리가 **끝까지 한 번** 동작
- 플랫폼 비용 **추적** 가능; 상한 알림 경로 정의
- 테스트 커버리지 목표 예: **60%+** (80%는 비필수)

**베타 운영**

- 1차 초대 **~10명**, DAU 등은 과도한 KPI 대신 **피드백·에러 로그** 우선
- API P99 등은 **10s 이하** 등 완화 목표 가능
